One engine, two faces

Double-click the exe and a window opens. Give it any argument and it stays a console tool. Both drive the same engine, and everything below ships in the one file.

Folders, ranked

Every folder ranked by recursive size with share bars. Double-click drills in, Backspace walks back up, and an Explorer-style tab lists the files that live right there.

Biggest and newest files

The same single scan pass feeds the biggest-files and most-recently-modified views. Sort by name, size or date, both directions, instant even at hundreds of thousands of rows.

Snapshot, then diff

Save the disk's state to a small .lda file before an install. Diff it later against the live disk or another snapshot: new files, deleted files, grown folders, exactly where.

Restore-point time machine

Windows already keeps shadow copies. Compare any folder against a restore point with no snapshot file at all, or browse the whole volume as it was days ago. Strictly read-only.

A window that teaches

The status line always shows the console command answering the same question, so the GUI doubles as a CLI tutorial. JSON and CSV output feed scripts and tickets directly.

Leaves no trace

No installer, no registry keys, no AppData, no temp files, no network code. Metadata-only reads; it writes only the snapshot you explicitly ask for. Delete the exe and it is gone.

The command line

Examples use lda for brevity: rename the exe freely, nothing depends on the name. Network shares, USB drives and mapped drives are first-class scan targets.

quick taste
$ lda                            # what is filling this drive
$ lda drives                     # what can I scan: fixed, USB, network
$ lda files C:\Users -min 100M   # biggest files
$ lda recent C:\ -since 2h       # modified in the last 2 hours
$ lda snap C:\ -out pre.lda      # before installing something
$ lda diff pre.lda C:\           # what did it drop, and where
$ lda diff -shadow 3 C:\Users    # compare against a restore point

Questions, answered

Windows SmartScreen warns about the download. Why?
The binary is new and not signed with an EV certificate, so SmartScreen has no reputation for it yet. Verify the SHA-256 hash against the one published above, then choose More info, Run anyway. The build is reproducible from source, so the published hash is checkable end to end.
Do I need administrator rights?
No. Without admin it simply counts the folders it cannot read and reports them as denied, with one ignorable notice. When admin is present it is used automatically. Elevation is never requested.
Does it send anything anywhere?
No. There is no network code in the binary at all: the source enforces a module-wide ban on Go's net and os/exec packages with a structural test. Nothing is uploaded, downloaded or executed behind your back.
Where does it keep its settings?
Nowhere. No registry keys, no AppData, no temp files. The only thing it ever writes is a snapshot file at the exact path you pass with -out. Delete the exe and every trace is gone.
What do restore points have to do with disk space?
Two things. Windows quietly keeps shadow copies, and their storage is classic invisible space: lda drives names those gigabytes. And every restore point is a free before picture: diff any folder against one, no snapshot file needed. Always read-only; shadow copies are never created, resized or deleted.
Is there a macOS build?
Not yet. Windows x64 and arm64 get the window plus CLI; the Linux x64 build is CLI-only. Each platform is a single static binary.
